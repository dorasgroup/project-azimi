# فاز سوم — برنامه‌ریزی جست‌وجوی چندزبانه

## وضعیت

وضعیت اجرایی: **کامل و آماده تأیید کاربر**  
تاریخ اجرا: ۱۴۰۵/۰۵/۰۵ (2026-07-27)

## هدف

رفع بخشی از خطاهای `no_topic_match` که ناشی از جست‌وجوی یک عبارت فارسی در منابع انگلیسی بود، بدون تغییر موضوع رصد و بدون کاهش کنترل دقت.

## معماری

فاز سوم دو value object و یک سرویس متمرکز اضافه کرد:

- `QueryVariant`: متن بازیابی، زبان، نوع گسترش و مفاهیم پوشش‌داده‌شده؛
- `TopicQueryPlan`: موضوع canonical تغییرناپذیر، زبان‌های هدف، مفاهیم اصلی و variantها؛
- `TopicQueryPlanner`: تولید حداکثر ۸ query کنترل‌شده.

تابع قدیمی `topic_search_queries` برای سازگاری حفظ شده و فقط facade این planner است. موضوع اصلی همچنان بدون تغییر به content scoring، document processing، legacy workflow engine و report می‌رسد؛ queryهای توسعه‌یافته صرفاً برای پیدا‌کردن URL استفاده می‌شوند.

## رفتار جست‌وجو

- منبع فارسی: موضوع اصلی و نسخه فشرده فارسی؛
- منبع انگلیسی: ترجمه مفهومی و aliasهای دقیق انگلیسی؛
- منبع فارسی/انگلیسی: هر دو گروه، با حذف تکرار؛
- منابع عربی/فرانسوی دارای English fallback: query انگلیسی قابل‌اعتماد؛
- مفهوم بدون ترجمه قابل‌اعتماد: عدم حدس‌زدن و fallback به موضوع canonical؛
- سقف خروجی: ۸ query، در مصرف search template حداکثر ۴ query.

نمونه موضوع «بررسی رویکرد رسانه‌های داخلی و خارجی به مسئله زن در ایران»:

- فارسی: موضوع کامل، `زن ایران`؛
- انگلیسی: `women iran`، `iranian women`، `women's rights iran`.

## کنترل drift

- `canonical_topic` هیچ‌گاه با query ترجمه‌شده جایگزین نمی‌شود.
- عبارت‌های instructional مانند «بررسی رویکرد رسانه‌ها» از compact query حذف می‌شوند.
- query قدیمی `Iran nuclear talks` برای موضوع صرفاً «مذاکرات ایران و آمریکا» حذف شد، چون مفهوم هسته‌ای را بدون درخواست کاربر اضافه می‌کرد.
- پذیرش سند همچنان حداقل دو مفهوم اصلی را برای موضوع چندمفهومی لازم دارد.
- افزایش recall فقط در discovery رخ می‌دهد و scoring سخت‌گیرانه بدون تغییر باقی مانده است.

## اتصال به providerها

- search seedهای HTML و templateهای اختصاصی از زبان profile منبع استفاده می‌کنند.
- GDELT با عبارت OR محدودشده به queryهای همان زبان و `domain:` منبع فراخوانی می‌شود.
- Common Crawl به query متنی نیاز ندارد و همچنان URLها را با موضوع canonical ارزیابی می‌کند.
- trace فاز دوم اکنون `query_languages` و `retrieval_queries` را نیز ثبت می‌کند.

## اصلاح capability پس از smoke

smoke زنده نشان داد `/search?q=` برای ایرنا 200، برای شرق و گاردین 404 و برای اکونومیست 403 است. قابلیت search برای سه منبع آخر غیرفعال شد تا بودجه روی RSS، sitemap، HTML، GDELT و Common Crawl مصرف شود. صفحه اصلی HTML همچنان seed می‌شود.

## ریسک و تصمیم

تحلیل اثر تغییر برای `topic_search_queries` ریسک بالا و برای `topic_concepts` ریسک بحرانی (۱۸ نماد و ۱۱ جریان) نشان داد. facade قبلی با قرارداد سازگار حفظ شد و semantic acceptance عربی/فرانسوی تغییر نکرد. توسعه آن بخش نیازمند corpus برچسب‌خورده جداگانه است.

## آزمون پذیرش

- تست‌های هدفمند planner، GDELT، profile routing و دقت: ۲۱ موفق؛
- suite کامل backend: ۱۲۶ موفق، ۴ skipped؛
- lint کل backend: موفق؛
- هر ۲۸ خانواده profile برای موضوع benchmark حداقل یک query و حداکثر ۸ query تولید کرد؛
- تست مثبت انگلیسی برای موضوع فارسی پذیرفته شد؛
- متن انگلیسی فقط درباره ایران و فاقد مفهوم زن رد شد؛
- Worker پس از اجرا بازراه‌اندازی و آماده شد.

## خارج از دامنه

- رتبه‌بندی هیبریدی lexical/semantic؛
- semantic acceptance کامل عربی، فرانسوی و عبری؛
- بازاجرای یک رصد production کامل؛
- حل egress سرور که طبق تصمیم کاربر از فاز اول معوق است.
