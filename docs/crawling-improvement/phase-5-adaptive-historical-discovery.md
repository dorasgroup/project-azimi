# فاز پنجم — بازیابی تاریخی تطبیقی

## وضعیت

وضعیت اجرایی: **کامل و آماده تأیید کاربر**  
تاریخ اجرا: ۱۴۰۵/۰۵/۰۵ (2026-07-27)

## مسئله رفع‌شده

fallback تاریخی از قبل وجود داشت، اما دو محدودیت recall داشت:

- GDELT کل بازه را با یک درخواست و سقف حداکثر ۲۵۰ نتیجه می‌خواند؛ در بازه پرتراکم، نتایج روزهای دیگر ممکن بود هرگز دیده نشوند.
- Common Crawl فقط page صفر CDX را می‌خواند؛ URL مرتبطی که در blockهای میانی یا انتهایی index بود کشف نمی‌شد.
- برای منبع فارسی، query فارسی به GDELT ارسال می‌شد؛ درحالی‌که DOC API به variant انگلیسی کنترل‌شده نیاز دارد.

## طراحی اجراشده

### برنامه‌ریزی مستقل

ماژول `historical_retrieval.py` فقط دو مسئولیت دارد:

1. تقسیم بازه تاریخ به حداکثر ۸ پنجره متوازن و جدیدبه‌قدیم؛
2. انتخاب حداکثر سه page با فاصله یکنواخت از کل index Common Crawl.

بودجه‌ها در `HistoricalRetrievalBudget` متمرکز هستند و قرارداد عمومی `CrawlPolicy` تغییر نکرده است.

### GDELT

- بازه ۹۰روزه به ۷ پنجره متوازن تقسیم می‌شود.
- ظرفیت `max_external_results` بین پنجره‌ها توزیع می‌شود.
- شکست یک پنجره مانع اجرای پنجره‌های دیگر نیست.
- برای هر source language، زبان `en` فقط به retrieval plan افزوده می‌شود.
- موضوع canonical، متن پردازش و موضوع گزارش تغییر نمی‌کنند.
- URL خارج از host منبع یا تاریخ مشاهده خارج از پنجره رد می‌شود.

### Common Crawl

- برای هر collection هم‌پوشان، `showNumPages=true` خوانده می‌شود.
- با `pageSize=1` حداکثر سه page از ابتدا، میانه و انتهای index نمونه‌برداری می‌شود.
- بودجه کل بین collection/pageها تقسیم می‌شود تا page اول تمام ظرفیت را مصرف نکند.
- فقط پاسخ موفق HTML، URL محتوامحور و host مجاز پذیرفته می‌شود.
- timestamp آرشیو همچنان تاریخ انتشار محسوب نمی‌شود.

## مشاهده‌پذیری

دو رویداد ساخت‌یافته اضافه شد:

- `crawl_gdelt_historical_discovery`: تعداد پنجره برنامه‌ریزی‌شده، موفق، ناموفق و تعداد نتیجه؛
- `crawl_common_crawl_historical_discovery`: تعداد collection، page تلاش‌شده/موفق، خطای page count و تعداد نتیجه.

هیچ query کامل، کلید API، متن سند یا داده محرمانه در trace ذخیره نمی‌شود.

## پذیرش

- تست‌های هدفمند: ۱۶ موفق؛
- suite کامل backend: ۱۳۵ موفق، ۴ skipped؛
- fixture قطعی ۹۰روزه: ۷ پنجره GDELT؛
- Common Crawl: pageهای ۰، ۵ و ۱۰ از index یازده‌صفحه‌ای خوانده شدند؛
- recall در fixture از 1/9 در رفتار قبلی به 9/9 رسید؛
- query منبع فارسی دارای variant انگلیسی و موضوع canonical بدون تغییر بود؛
- تماس شبکه، legacy workflow engine و نوشتن دیتابیس در verifier: صفر؛
- کنترل host، dedupe، سقف نتیجه و تحمل شکست provider حفظ شد.

## وضعیت egress زنده

پذیرش قطعی این فاز به شبکه عمومی وابسته نیست. smoke واقعی GDELT/Common Crawl باید بعد از استقرار روی سرور نیز اجرا شود، چون رفع محدودیت egress محیط محلی طبق تصمیم کاربر از فاز اول تا زمان انتقال به سرور معوق مانده است.
