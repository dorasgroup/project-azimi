# نسخه بازیابی v4

این نسخه وضعیت کامل پروژه «رصد و تحلیل» در تاریخ ۳۰ خرداد ۱۴۰۵ را پس از اتصال مجدد و راه‌اندازی پایدار سرویس‌های legacy workflow engine محلی و ثبت لاگ‌های عیب‌یابی آن، ثبت می‌کند.

## اجزای نسخه

- کد پروژه در Git tag با نام `v4`
- Git bundle مستقل در مسیر `D:\pr\10_versions\v4\rasad-analysis-v4.bundle`
- آرشیو کد در مسیر `D:\pr\10_versions\v4\rasad-analysis-v4-code.zip`
- تنظیمات محلی در مسیر `D:\pr\10_versions\v4\runtime\.env`
- dump کامل PostgreSQL در مسیر `D:\pr\10_versions\v4\runtime\postgres-v4.dump`
- فایل‌های runtime و گزارش‌ها در مسیر `D:\pr\10_versions\v4\runtime\storage`
- فهرست checksum فایل‌های snapshot در مسیر `D:\pr\10_versions\v4\SHA256SUMS.txt`

## نکات مهم v4

- کانتینرهای داکر legacy workflow engine مجدداً با دانلود تک‌تک ایمیج‌ها پیکربندی و راه‌اندازی شدند و وضعیت اتصالات به موفقیت برگشت.
- خطای ۴۰۲ مربوط به اعتبار سرویس‌دهنده بیرونی OpenRouter شناسایی و ریشه‌یابی شد.
- کدهای پروژه شامل تغییرات چیدمان دو ستونه صفحات رصد تازه و منابع، ارتقای ناوبری تب‌ها، آیکون مدرن رادار، آواتار چرخ‌دنده تنظیمات، نوارهای لودینگ متحرک پیشرفت کار، و بهینه‌سازی سرعت موتور خزش ثبت نهایی شدند.
- نسخه‌های `v1` و `v2` و `v3` همچنان به‌عنوان نقاط بازیابی قبلی باقی مانده‌اند.

## بازگردانی کد

برای بازگردانی همین working tree:

```powershell
git switch --detach v4
```

برای ساخت یک پوشه تازه از نسخه مستقل:

```powershell
git clone D:\pr\10_versions\v4\rasad-analysis-v4.bundle D:\pr\10-restored-v4
Set-Location D:\pr\10-restored-v4
git switch --detach v4
```

## بازگردانی داده‌های runtime

قبل از بازگردانی داده‌ها، سرویس‌های پروژه باید متوقف شوند. سپس فایل `.env` و پوشه `storage` از snapshot به ریشه پروژه کپی و dump دیتابیس داخل PostgreSQL بازیابی می‌شود.

نمونه مسیرهای مورد نیاز:

```powershell
Copy-Item D:\pr\10_versions\v4\runtime\.env D:\pr\10\.env -Force
Remove-Item D:\pr\10\storage -Recurse -Force
Copy-Item D:\pr\10_versions\v4\runtime\storage D:\pr\10\storage -Recurse
```

برای بازیابی دیتابیس PostgreSQL:

```powershell
# متوقف کردن سرویس‌های API و Worker
docker compose -f docker/compose.yml stop api worker

# حذف و ساخت مجدد دیتابیس
docker compose -f docker/compose.yml exec -T postgres dropdb -U rasad rasad --if-exists
docker compose -f docker/compose.yml exec -T postgres createdb -U rasad rasad

# بازیابی dump دیتابیس
docker compose -f docker/compose.yml exec -T postgres pg_restore -U rasad -d rasad -v < D:\pr\10_versions\v4\runtime\postgres-v4.dump

# راه‌اندازی مجدد سرویس‌ها
docker compose -f docker/compose.yml start api worker
```

نسخه snapshot محلی شامل اطلاعات حساس تنظیمات است و نباید در مخزن عمومی یا فضای اشتراکی آپلود شود.
