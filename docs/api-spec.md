# قرارداد API بک‌اند

## وضعیت سند

- فاز: چهار، طراحی API بک‌اند
- نسخه قرارداد: `v1`
- پیشوند همه مسیرها: `/api/v1`
- پیاده‌سازی منطق هر قابلیت در فاز تخصصی همان قابلیت انجام می‌شود. در فاز چهار مسیرها، schemaها، سطح دسترسی و OpenAPI تثبیت شده‌اند.

## قواعد مشترک

- ورودی و خروجی API از JSON و نام فیلدهای انگلیسی استفاده می‌کند.
- احراز هویت مسیرهای محافظت‌شده با access token از نوع Bearer انجام می‌شود.
- refresh token برای تمدید نشست از مسیر `POST /auth/refresh` در نظر گرفته شده است.
- فهرست‌ها پارامترهای `page` و `page_size` دارند؛ مقدار `page_size` بین ۱ تا ۱۰۰ است.
- پاسخ فهرست‌ها شامل `items` و `meta` با فیلدهای `page`، `page_size`، `total` و `pages` است.
- شناسه منابع، کاربران، jobها، گزارش‌ها و هویت ربات UUID است.
- تاریخ‌های سیستمی با ISO 8601 مبادله می‌شوند. job رصد، تاریخ شمسی نمایشی و تاریخ میلادی قابل پردازش را هم‌زمان دریافت می‌کند.

## قالب خطا

تمام خطاهای HTTP و اعتبارسنجی در قالب زیر بازگردانده می‌شوند:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Request validation failed",
    "details": {}
  }
}
```

کدهای متداول عبارت‌اند از `401` برای نبود احراز هویت، `403` برای نبود دسترسی، `404` برای نبود رکورد و `422` برای ورودی نامعتبر. مسیرهایی که در فاز چهار فقط قراردادشان تثبیت شده بود، در فازهای بعدی پیاده‌سازی شده‌اند و در نسخه فعلی نباید پاسخ ثابت `501` داشته باشند.

## سطح دسترسی

| سطح | شرح |
| --- | --- |
| عمومی | health، login و refresh |
| کاربر احرازشده | پروفایل، مشاهده منابع و هویت فعال، jobهای رصد و گزارش‌های متعلق به کاربر |
| `super_admin` | ایجاد و تغییر منابع، مدیریت هویت ربات و CRUD کاربران |

مالکیت job و گزارش در لایه سرویس کنترل می‌شود؛ کاربر عادی فقط داده‌های متعلق به خود را می‌بیند و مدیر ارشد به همه داده‌ها دسترسی دارد.

## مسیرها

| گروه | متد و مسیر | دسترسی | نتیجه اصلی |
| --- | --- | --- | --- |
| سلامت | `GET /health` | عمومی | وضعیت API، دیتابیس، Redis و legacy workflow engine |
| احراز هویت | `POST /auth/login` | عمومی | access token |
| احراز هویت | `POST /auth/refresh` | عمومی با refresh token | access token جدید |

| احراز هویت | `PUT /auth/change-password` | کاربر | پیام نتیجه |
| منابع | `GET /sources` | کاربر | فهرست صفحه‌بندی‌شده |
| منابع | `POST /sources` | مدیر ارشد | منبع جدید |
| منابع | `PUT /sources/{source_id}` | مدیر ارشد | منبع به‌روزشده |
| منابع | `DELETE /sources/{source_id}` | مدیر ارشد | پیام نتیجه |
