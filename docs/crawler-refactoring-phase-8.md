# فاز هشتم بازطراحی خزش: رتبه‌بندی و پذیرش نهایی

## هدف

در discovery هیبریدی ممکن است یک provider صدها URL تولید کند و پیش از رسیدن نتایج مطمئن RSS، sitemap یا index تاریخی، سقف `max_pages` را پر کند. این فاز selection را از sort ساده به رتبه‌بندی evidence-based و تخصیص متنوع بودجه خزش تبدیل می‌کند.

## امتیاز کاندید

`CandidateRanker` برای هر URL این شواهد را در نظر می‌گیرد:

- تعداد مفهوم‌های موضوعی موجود در URL یا عنوان؛
- تاریخ شناخته‌شده و داخل بازه؛
- تأیید یک URL توسط چند provider مستقل؛
- اعتبار نسبی provenance مانند RSS، sitemap، search و archive؛
- وجود عنوان و شباهت URL به مسیر محتوایی.

تاریخ شناخته‌شده خارج بازه پیش از رتبه‌بندی حذف می‌شود. URL بدون تاریخ حذف نمی‌شود، چون تاریخ معتبر آن پس از fetch توسط resolver فاز سوم بررسی خواهد شد.

## تنوع provider

پیش از پرکردن باقی ظرفیت، بهترین کاندید موضوعی از providerهای مستقل انتخاب می‌شود. سپس باقی URLها با جریمه تکرار provider رتبه‌بندی می‌شوند. این رفتار از flood شدن بودجه توسط search یا HTML جلوگیری می‌کند.

سیاست‌ها:

- `candidate_diversity_enabled`
- `candidate_provider_slots`
- `candidate_repeat_provider_penalty`

با خاموش‌کردن diversity، سیستم فقط از رتبه‌بندی امتیازی deterministic استفاده می‌کند.

## تفکیک مسئولیت‌ها

- `CandidateRanker`: فیلتر تاریخ، scoring و allocation؛
- `CrawlOrchestrator`: هماهنگی و delegation؛
- `CrawlDiagnosticsBuilder`: ثبت شمار providerهای کشف و انتخاب؛
- `ContentProcessor`: همچنان مسئول تأیید نهایی تاریخ و relevance متن کامل است.

## معیار پذیرش

- flood یک provider سایر providerهای معتبر را حذف نکند؛
- topic، تاریخ و provenance چندمنبعی اولویت داشته باشند؛
- URL تاریخ‌دار خارج بازه انتخاب نشود؛
- URL بدون تاریخ برای بررسی دقیق پس از fetch باقی بماند؛
- ترتیب deterministic باشد؛
- رصد تاریخی نمونه، regression کامل و smoke worker عبور کنند.

## اصلاحات کشف‌شده در پذیرش زنده

آزمون رصد واقعی نشان داد رتبه‌بندی به‌تنهایی کافی نیست. سه گلوگاه تکمیلی نیز در همین فاز برطرف شدند:

- کفایت کشف محلی اکنون فقط با لینک‌های مرتبط و دارای تاریخ معتبر در بازه سنجیده می‌شود؛ انبوه URLهای بدون تاریخ دیگر fallback تاریخی را خاموش نمی‌کند.
- sitemapهای seed نیز پیش از مصرف بودجه بر اساس سال و ماه میلادی/شمسی مرتب می‌شوند؛ بنابراین sitemap سال جاری، مسیر تاریخی هدف را از صف خارج نمی‌کند.
- Browser fallback از cache پوسته‌های ناقص استفاده نمی‌کند و تنها وقتی موفق است که HTML یا Markdown متن قابل‌مشاهده کافی تولید کند.

در برنامه‌ریز موضوع نیز عبارت‌های عمومی حذف و مترادف‌های فارسی `زن`، `زنان`، `بانوان` و `دختران` یک مفهوم واحد در نظر گرفته شدند. برای موضوع‌های دو‌مفهومی مانند «زن در ایران»، وجود هر دو مفهوم برای پذیرش relevance الزامی است.

## نتیجه پذیرش نهایی

اسکریپت `verify_historical_monitoring_acceptance.py` همان موضوع و بازه رصد ناموفق قبلی را بدون نوشتن در دیتابیس و بدون فراخوانی legacy workflow engine اجرا می‌کند. اجرای نهایی روی IRNA از ۲۵۰۰ کاندید، ۲۰ صفحه را واکشی و ۴ سند مرتبط را برای پردازش آماده کرد.
