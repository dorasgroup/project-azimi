# ADR 001: انتخاب الگوی معماری (Modular Monolith در برابر Microservices)

> **وضعیت: معماری هدف، هنوز در Production فعال نیست.** معماری جاری در
> `docs/architecture/current-production.md` ثبت شده است.

## Context
سیستم مدیریت اسناد و چت مبتنی بر هوش مصنوعی نیازمند پردازش امن فایل‌ها، مدیریت دسترسی‌ها (Tenant Isolation) و هم‌زمان چت استریم با هوش مصنوعی است. تیم توسعه در مرحله شروع (MVP) قرار دارد.

## Decision
ما برای هسته کسب‌وکار (Core API) از الگوی **Modular Monolith** استفاده خواهیم کرد. با این حال، به دلیل پروفایل‌های پردازشی متفاوت، کامپوننت‌های **AI Gateway** (که نیازمند مدیریت صدها اتصال همزمان SSE است) و **Ingestion Worker** (که پردازش‌های سنگین CPU-bound برای OCR و استخراج متن انجام می‌دهد) از هسته اصلی جدا شده و به صورت سرویس‌های مستقل راه‌اندازی می‌شوند.

## Consequences
- **مثبت:** کاهش پیچیدگی‌های استقرار در مرحله اول، جلوگیری از Network Latency بی‌دلیل بین ماژول‌های User و Document، دیباگ راحت‌تر در فازهای اولیه.
- **منفی:** اگر ترافیک بخش مدیریت اسناد ناگهان زیاد شود، کل Core API باید با هم اسکیل (Scale) شود.
- **ریسک:** خطر تنیدگی کدها (Spaghetti Code). این ریسک با الزام استفاده از معماری لایه‌ای (Clean Architecture) در ماژول‌های Core API مدیریت می‌شود.

## Revisit Trigger
زمانی که اندازه تیم از ۱۰ نفر فراتر رود یا زمانی که بار پردازشی بخش Authorization به گلوگاه (Bottleneck) سیستم تبدیل شود.
