# نسخه بازیابی v3

این نسخه وضعیت کامل پروژه «رصد و تحلیل» در تاریخ ۱۹ خرداد ۱۴۰۵ را پس از اصلاحات عمیق خزش، تاریخ شمسی، پشتیبانی منابع غیرفارسی، افزایش کیفیت گزارش‌ها و رفع خطای رصد Haaretz ثبت می‌کند.

## اجزای نسخه

- کد پروژه در Git tag با نام `v3`
- Git bundle مستقل در مسیر `D:\pr\10_versions\v3\rasad-analysis-v3.bundle`
- آرشیو کد در مسیر `D:\pr\10_versions\v3\rasad-analysis-v3-code.zip`
- تنظیمات محلی در مسیر `D:\pr\10_versions\v3\runtime\.env`
- dump کامل PostgreSQL در مسیر `D:\pr\10_versions\v3\runtime\postgres-v3.dump`
- فایل‌های runtime و گزارش‌ها در مسیر `D:\pr\10_versions\v3\runtime\storage`
- فهرست checksum فایل‌های snapshot در مسیر `D:\pr\10_versions\v3\SHA256SUMS.txt`

## نکات مهم v3

- همه تاریخ‌های نمایشی و تاریخ‌های گزارش‌ها با تقویم شمسی نمایش داده می‌شوند و قرارداد گزارش legacy workflow engine نیز از بازه شمسی استفاده می‌کند.
- خزش برای بازه‌های طولانی و منابع متعدد عمیق‌تر شده و برای منابع موجود، سقف صفحات به‌صورت پیش‌فرض روی مقدار بالاتری تنظیم شده است.
- منابع غیرفارسی حفظ می‌شوند، زبان سند تشخیص داده می‌شود و خروجی گزارش نهایی باید فارسی باشد.
- تطبیق موضوع‌های فارسی با منابع انگلیسی/غیرفارسی تقویت شده است؛ مانند مذاکرات ایران و آمریکا، حمله ایران به اسرائیل، حملات، موشک و واژه‌های مشابه.
- extractor از ساختارهای مقاله‌ای معمولی و ساختار `LiveBlogPosting` پشتیبانی می‌کند؛ این مورد خطای رصد Haaretz را که سند آماده تولید نمی‌کرد رفع کرد.
- timeout و مدیریت خطای legacy workflow engine پایدارتر شده و خطاهای بدون پیام به پیام فارسی قابل فهم تبدیل می‌شوند.
- رصدهای اخیر قابلیت ویرایش، اجرای مجدد و حذف دارند و گزارش حذف‌شده، رصد مرتبط را نیز از فهرست اخیر حذف می‌کند.
- نسخه‌های `v1` و `v2` همچنان به‌عنوان نقاط بازیابی قبلی باقی مانده‌اند.

## بازگرداندن کد

برای بازگرداندن همین working tree:

```powershell
git switch --detach v3
```

برای ساخت یک پوشه تازه از نسخه مستقل:

```powershell
git clone D:\pr\10_versions\v3\rasad-analysis-v3.bundle D:\pr\10-restored-v3
Set-Location D:\pr\10-restored-v3
git switch --detach v3
```

## بازگرداندن داده‌های runtime

قبل از بازگرداندن داده‌ها، سرویس‌های پروژه باید متوقف شوند. سپس فایل `.env` و پوشه `storage` از snapshot به ریشه پروژه کپی و dump دیتابیس داخل PostgreSQL بازیابی می‌شود.

نمونه مسیرهای مورد نیاز:

```powershell
Copy-Item D:\pr\10_versions\v3\runtime\.env D:\pr\10\.env -Force
Remove-Item D:\pr\10\storage -Recurse -Force
Copy-Item D:\pr\10_versions\v3\runtime\storage D:\pr\10\storage -Recurse
```

نسخه snapshot محلی شامل اطلاعات حساس تنظیمات است و نباید در مخزن عمومی یا فضای اشتراکی آپلود شود.
