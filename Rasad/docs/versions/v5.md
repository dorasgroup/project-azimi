# نسخه بازیابی v5

این نسخه وضعیت کامل پروژه «رصد و تحلیل» در تاریخ ۳۱ خرداد ۱۴۰۵ را پس از بهبود انتخابگر تاریخ شمسی، ساده‌سازی فرم هویت تحلیلگر، افزودن گزینه‌های انتخابی کشویی لحن و سبک، و رفع خطای اعتبارسنجی پکیج‌های کانتینرها ثبت می‌کند.

## اجزای نسخه

- کد پروژه در Git tag با نام `v5`
- Git bundle مستقل در مسیر `D:\pr\10_versions\v5\rasad-analysis-v5.bundle`
- آرشیو کد در مسیر `D:\pr\10_versions\v5\rasad-analysis-v5-code.zip`
- تنظیمات محلی در مسیر `D:\pr\10_versions\v5\runtime\.env`
- dump کامل PostgreSQL در مسیر `D:\pr\10_versions\v5\runtime\postgres-v5.dump`
- فایل‌های runtime و گزارش‌ها در مسیر `D:\pr\10_versions\v5\runtime\storage`
- فهرست checksum فایل‌های snapshot در مسیر `D:\pr\10_versions\v5\SHA256SUMS.txt`

## نکات مهم v5

- اولویت بارگذاری کدهای توسعه با افزودن `PYTHONPATH: /app` به فایل `compose.yml` در کانتینرها اعمال شد که مانع از لود پکیج‌های منقضی در `site-packages` می‌گردد.
- تست پذیرش جریان رصد کامل (`verify_monitoring_flow.py`) با تغییر دامنه تست به `blog.python.org` و دریافت تاریخ‌های نشر معتبر، بازنویسی شده و بدون خطا در وضعیت `completed` پاس شد.
- کدهای فرانت‌اند اصلاح شدند تا فیلدهای هویت تحلیلگر («توضیح» و «شرح نقش») در فیلد واحد «نقش تحلیلگر» ادغام شوند.
- فیلدهای متنی «لحن» و «سبک تحلیل» به گزینه‌های از پیش تعریف‌شده و کشویی (`select`) تبدیل شدند تا از تایپ دستی کاربر جلوگیری شود.
- نسخه‌های قبلی بازیابی (`v1`, `v2`, `v3`, `v4`) همچنان پابرجا و معتبر هستند.

## بازگردانی کد

برای بازگردانی همین working tree:

```powershell
git switch --detach v5
```

برای ساخت یک پوشه تازه از نسخه مستقل:

```powershell
git clone D:\pr\10_versions\v5\rasad-analysis-v5.bundle D:\pr\10-restored-v5
Set-Location D:\pr\10-restored-v5
git switch --detach v5
```

## بازگردانی داده‌های runtime

قبل از بازگردانی داده‌ها، سرویس‌های پروژه باید متوقف شوند. سپس فایل `.env` و پوشه `storage` از snapshot به ریشه پروژه کپی و dump دیتابیس داخل PostgreSQL بازیابی می‌شود.

نمونه مسیرهای مورد نیاز:

```powershell
Copy-Item D:\pr\10_versions\v5\runtime\.env D:\pr\10\.env -Force
Remove-Item D:\pr\10\storage -Recurse -Force
Copy-Item D:\pr\10_versions\v5\runtime\storage D:\pr\10\storage -Recurse
```

برای بازیابی دیتابیس PostgreSQL:

```powershell
# متوقف کردن سرویس‌های API و Worker
docker compose -f docker/compose.yml stop api worker

# حذف و ساخت مجدد دیتابیس
docker compose -f docker/compose.yml exec -T postgres dropdb -U rasad rasad --if-exists
docker compose -f docker/compose.yml exec -T postgres createdb -U rasad rasad

# بازیابی dump دیتابیس
docker compose -f docker/compose.yml exec -T postgres pg_restore -U rasad -d rasad -v < D:\pr\10_versions\v5\runtime\postgres-v5.dump

# راه‌اندازی مجدد سرویس‌ها
docker compose -f docker/compose.yml start api worker
```

نسخه snapshot محلی شامل اطلاعات حساس تنظیمات است و نباید در مخزن عمومی یا فضای اشتراکی آپلود شود.
